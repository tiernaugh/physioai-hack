# Application Instructions

These instructions extend the repository-level `AGENTS.md` for implementation work in this directory.

- Read the selected concept documents before scaffolding or changing architecture.
- Optimize for the documented golden path and acceptance criteria.
- Do not add features solely to showcase another API or sponsor.
- Make the environment's context, trigger, or action visible in the working experience.
- Use structured data between agent steps where practical.
- Keep consequential actions previewable or approval-gated as defined in the workflow.
- Make uncertainty and failure visible to the user.
- Prefer a simple fallback over a fragile integration if it preserves the central product claim.
- Keep demo fixtures explicit and distinguish live, seeded, mocked, and manually operated behaviour.
- Update this directory's `README.md` with exact setup and demo instructions as the app evolves.
- Run checks proportionate to the change and protect teammate work already in progress.
