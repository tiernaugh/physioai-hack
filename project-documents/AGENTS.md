# Project Document Instructions

These instructions extend the repository-level `AGENTS.md` for work in this directory.

- Preserve raw transcripts as source material. Do not silently rewrite them for accuracy or clarity.
- Put summaries, interpretations, and inferred implications in separate working documents.
- Keep descriptive ideation prompts open enough to generate unexpected combinations.
- Do not turn a weak idea into a strong-sounding pitch before testing whether the environment is essential.
- When proposing or evaluating a concept, explicitly cover the user, environment, trigger, available context, agent action, tools, human control, contextual advantage, demo moment, smallest build, judging strengths, and risks.
- Keep the selected concept internally consistent across its files. Record significant changes in the decision log.
- Use `tickets/` for executable work. Keep strategic context and enduring product decisions in the main project documents.
- Prefer concrete examples, observable behaviours, and testable requirements over abstract claims.
- Add dates to decisions and time-sensitive notes using `YYYY-MM-DD`.
